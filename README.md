# gnam v7.1 · Food Operating System

Static app for GitHub Pages. No runtime API is required by the browser.

## Included

- 7-day / 14-meal planner with lunch + dinner.
- Four complete starter baskets: ~€35 Smart / ~€55 Balanced / ~€65 Comfort / ~€75 Plus; Comfort is the requested middle tier between Balanced and Plus.
- Presets include fruit plus a pantry kit of salt, pepper, curry, turmeric, cumin, paprika, oregano, rosemary, basil, parsley, thyme, sage, mint, bay leaf, chilli, ginger, cinnamon, nutmeg, vinegar, balsamic vinegar, soy sauce and vegetable stock.
- Recipes cannot use ingredients hidden from the shopping list. Spices and herbs are first-class ingredients.
- Common ingredient autocomplete with thousands of normalized forms, including synonyms such as burro di arachidi / burro di noccioline / peanut butter.
- Smart expiry suggestions for common foods; the package label date always wins.
- Live grocery-quality check while the inventory changes.
- 1–100 grocery score covering vegetables, fruit, protein-family diversity, legumes/cereals, herbs/spices and fresh + pantry mix.
- Detailed day-level nutrition: energy, protein, carbohydrate %, fat %, fibre, calcium, iron, vitamin C, folate, potassium and omega-3 estimate.
- Day click opens the numeric reasoning behind the OK status and cites WHO / EFSA / USDA.
- The planner scores the complete lunch+dinner pair, avoids the same principal protein at lunch and dinner, penalizes ingredient overlap and tries to diversify the whole week.
- Fruit is explicitly consumed by the plan and comes from the shopping inventory.
- If a manual basket cannot make every day OK, Gnam shows concrete add-on examples with quantities rather than inventing foods.
- No fake freezer/waste UI. Those features were removed until they can be supported by a real inventory model.
- Week fingerprints are stored locally so the same exact menu is not intentionally repeated when alternatives exist.
- Online recipe database is generated server-side by GitHub Actions and stored as a static JS file. The browser never calls TheMealDB, avoiding CORS/rate-limit failures.

## GitHub Pages

Upload the repository contents to the root of the GitHub repository and enable:

Settings → Pages → Deploy from a branch → `main` → `/ (root)`.

## Daily recipe database update

The workflow is `.github/workflows/update-recipes.yml`: it runs once on the first repository update that changes the updater, then daily at 03:17 UTC, plus manual dispatch.

The workflow calls TheMealDB's official V1 search-by-letter endpoints server-side, validates the complete recipe payload, rejects ambiguous/incomplete ingredient measures, normalizes ingredients and writes/merges `online-recipes.generated.js` up to 900 validated recipes, preserving previously accepted recipes so the catalogue can grow as the source grows.

The workflow is configured to refuse to overwrite the previous database if fewer than 500 recipes pass QA.

### API key

The script accepts `THEMEALDB_API_KEY` as a repository secret. The free test key is `1`; for a public production application TheMealDB's current API guide recommends a supporter/production key. See:

- https://www.themealdb.com/docs_api_guide.php
- https://www.themealdb.com/api.php

Add the repository secret under:

Settings → Secrets and variables → Actions → New repository secret → `THEMEALDB_API_KEY`.

The static planner itself does not need this secret at runtime.

## Scientific framing

The app uses evidence-informed planning rules rather than claiming to provide medical nutrition advice.

- WHO: at least 400 g/day of fruit and vegetables in adults and at least 25 g/day naturally occurring dietary fibre; emphasis on whole grains, fruit, vegetables, legumes, nuts and lower salt/free sugar intake.
- EFSA: carbohydrate reference range 45–60 E%, fat 20–35 E%; protein PRI 0.83 g/kg/day for healthy adults.
- Gnam applies these to the planned lunch+dinner block, not to the entire day, because breakfast and snacks are outside the app's plan. The UI makes this limitation explicit.

Sources:
- https://www.who.int/health-topics/healthy-diet
- https://www.efsa.europa.eu/en/topics/topic/dietary-reference-values
- https://fdc.nal.usda.gov/

## Important QA rule

A remote recipe is only accepted when its source payload survives validation. If a substantial ingredient or quantity cannot be interpreted, the recipe is rejected rather than silently simplified. Ambiguous measures such as "for frying", "as needed" or "to taste" are not converted to arbitrary 1 g values. Household water/ice are treated as non-shopping household staples.
